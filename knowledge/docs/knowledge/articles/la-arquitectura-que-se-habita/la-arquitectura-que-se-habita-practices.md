# Practices — La arquitectura que se habita

## Quick checklist (≤10 ítems)
- [ ] Documentar quiénes “habitan” cada componente y sus necesidades.
- [ ] Ejecutar walkthroughs periódicos usando el sistema como cliente real.
- [ ] Priorizar historias que eliminen fricciones observadas en campo.
- [ ] Evaluar nuevas tecnologías contra criterios de simplicidad y fiabilidad.
- [ ] Registrar feedback de usuarios en un backlog accesible.
- [ ] Coordinar sesiones de co-diseño con equipos de soporte y operaciones.
- [ ] Publicar decisiones arquitectónicas con racionales humanos explícitos.
- [ ] Revisar indicadores de satisfacción y confiabilidad junto con las releases.

## How-to (pasos accionables)
1) Mapear journeys críticos identificando emociones, fricciones y expectativas de usuarios y operadores.  
2) Diseñar experimentos controlados (shadowing, pruebas internas) donde el equipo técnico viva esos journeys y capture evidencias.  
3) Incorporar resultados en decisiones arquitectónicas priorizando simplicidad, observabilidad y comunicación transparente con interesados.

## KPIs / Leading indicators
- Índice de satisfacción del usuario interno/externo por release.
- Cantidad de fricciones removidas vs. detectadas en shadowing.
- Tiempo medio para resolver feedback crítico recibido.
- Porcentaje de decisiones tecnológicas con criterio de propósito documentado.
