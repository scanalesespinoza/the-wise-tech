# Practices — 🛠️ Architecting Open Source Teams: Building People Before Platforms

## Quick checklist (≤10 ítems)
- [ ] Crear guía de contribución ligera con visión, contacto y pasos claros.
- [ ] Conectar iniciativas open source a OKR u objetivos de negocio visibles.
- [ ] Lanzar demos frecuentes para mostrar avances y aprendizajes.
- [ ] Establecer rituales de reconocimiento y agradecimiento público.
- [ ] Mantener tablero de issues accesible con prioridades transparentes.
- [ ] Garantizar acompañamiento de mentores o maintainers por iniciativa.
- [ ] Medir diversidad de contribuciones (docs, código, soporte).
- [ ] Revisar trimestralmente sostenibilidad (tiempo, voluntarios, impacto).

## How-to (pasos accionables)
1) Diseñar un playbook de colaboración que defina roles, criterios de entrada y canales de comunicación.  
2) Integrar entregables open source en la planificación oficial, asignando capacidad y reconociendo logros en evaluaciones.  
3) Facilitar espacios de “libertad dirigida” como horas reservadas para experimentos con acompañamiento de líderes técnicos.

## KPIs / Leading indicators
- Número de contribuyentes activos y retención trimestral.
- Proporción de aportes no code (docs, soporte) reconocidos públicamente.
- Tiempo medio de respuesta a nuevas contribuciones.
- Impacto en objetivos de negocio asociados (features entregadas, problemas resueltos).
