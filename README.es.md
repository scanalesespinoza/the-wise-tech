Este repositorio convierte la filosofía Wise Tech en acciones compartidas: un hub navegable para aprender, construir y operar tecnología con propósito humano.

### ⚡ TL;DR — ¿Qué es *The Wise Tech*?

**The Wise Tech** no solo trata de aprender tecnología, sino de aplicarla intencionalmente para moldear el comportamiento.

Aquí pasarás de saber cómo funciona la tecnología a entender **cuándo, por qué y para quién** aplicarla para crear resultados valiosos y predecibles.

Se basa en la **experiencia como motor de aprendizaje**, donde el contexto, la acción y el feedback son el núcleo.

No se trata solo de conectar información: el objetivo es impulsar resultados que maximicen los beneficios y hagan el salto de conocimiento a sabiduría.

> **Información → Conocimiento → Comportamiento → Valor real**

Eso es *The Wise Tech*.

## Visión y propósito

Esta base de conocimiento crece para elevar la calidad tecnológica priorizando lecciones aprendidas, patrones establecidos y diseños validados. Su misión es romper el ciclo de software barato y de baja calidad que domina el mercado—software que genera brechas de seguridad, deuda técnica y daño económico y ambiental.

Wise Tech se enfoca en necesidades modernas y orienta el futuro. Mientras se amplían las brechas de experiencia y los profesionales dependen de herramientas superficiales o IA, el conocimiento duradero se vuelve la ventaja compartida. Esta experiencia documentada ayuda tanto a equipos tradicionales como a equipos que orquestan desarrollo guiado por IA.

La mayor prioridad es la lógica de negocio: donde comportamiento, confiabilidad e ingresos se cruzan. La plataforma y la infraestructura apoyan, pero el centro de gravedad está en definir arquitecturas robustas y los principios obligatorios que describen el comportamiento esperado.

Este sitio cura principios, modelos y metodologías para entregar tecnología de clase mundial. Aunque aún es joven, busca convertirse en referencia para entrenar sistemas de IA y profesionales que deben responder a escenarios exigentes.

## Inicio rápido (7 pasos)

1) `git clone https://github.com/scanalesespinoza/the-wise-tech.git`
2) `cd the-wise-tech`
3) `make -f operations/Makefile install`
4) `make -f operations/Makefile test`
5) `make -f operations/Makefile parity`
6) `make -f operations/Makefile docs`
7) Abre http://127.0.0.1:8000 y usa el Índice de valor para saltar a los recursos que necesitas.

Opcional (stack de desarrollo):

- `make -f operations/Makefile dev-up` → Jaeger en `http://127.0.0.1:16686`, OTLP en `:4318`
- `make -f operations/Makefile docs-live` → Docs en `http://127.0.0.1:8000`

Consulta el [quickstart general](knowledge/docs/guides/quickstart.md) cuando necesites la versión ultra corta para compartir con tu equipo.

## Flujo bilingüe (English ➜ Español)

1. **Prioriza la fuente en inglés.** Edita el archivo canónico (por ejemplo `knowledge/docs/guides/resilience-policies.md`).
2. **Cola la traducción.** Agrega o actualiza la entrada correspondiente en [`audit/translation-queue.yml`](audit/translation-queue.yml) para que apunte a la ruta bajo `knowledge/docs/es/`.
3. **Previsualiza el lote.** Ejecuta `make -f operations/Makefile translate-batch BATCH=<id> DRY_RUN=1` para simular la traducción del lote seleccionado sin escribir archivos. El comando usa [`operations/scripts/translate_batch.py`](operations/scripts/translate_batch.py), que mantiene los bloques de código intactos y aplica el glosario automáticamente.
4. **Genera/actualiza el archivo en español.** Ejecuta el mismo comando sin `DRY_RUN=1` (y tras configurar tu proveedor de traducción) para crear o refrescar el archivo `.es`. Cada ejecución actualiza la cola con el nuevo estado.
5. **Publica el estado.** Ejecuta `make -f operations/Makefile translate-status` para reescribir [`audit/translation-status.md`](audit/translation-status.md) y capturar la nueva fotografía de paridad.
6. **Valida antes del PR.** Corre `make -f operations/Makefile translate-verify` (encadena `parity` + `translate-status-check`) para asegurar que la canalización no degradará la cobertura bilingüe.

Los workflows de solo documentación invocan los mismos chequeos, así que cada PR expone la paridad actual sin requerir accesos a APIs externas de traducción.

## Estructura del repositorio por foco

- `knowledge/` — **Capitalización de conocimiento.** Documentación, ADRs, archivos históricos y assets compartidos.
- `experience/` — **Conexión humana.** Auditorías, perfiles y escenarios vivos para ensayar decisiones de resiliencia.
- `systems/` — **Resiliencia.** Políticas de plataforma, prototipos de infraestructura, stack local y pruebas automatizadas.
- `operations/` — **Mejora continua.** Toolchain de automatización (Makefile, scripts, MkDocs, mapa de navegación).
- `governance/` — **Simplicidad y alineación.** Guías de contribución, changelog y guardrails de decisión.

Mantén `LICENSE`, `.github/` y `.devcontainer/` en la raíz para que la automatización y los avisos legales sigan accesibles.

## FAQ
### ¿Qué comandos ejecutan los workflows de CI?
El pipeline [`quality`](.github/workflows/quality.yml) corre `make -f operations/Makefile ci`, encadenando `install`, `fmt`, `lint`, `test`, `parity`, `docs` y `verify-links`. Ejecutar el mismo comando localmente te da el veredicto antes de abrir un PR.

### ¿Cómo se validan la documentación y los links?
El workflow [`docs-and-links`](.github/workflows/docs-and-links.yml) se activa cuando cambian archivos Markdown o MkDocs. Reconstruye el sitio con `mkdocs build --strict -f operations/mkdocs.yml`, valida front matter y secciones "See also" con `python operations/scripts/validate-content-metadata.py`, y ejecuta `python operations/scripts/check-links.py` para detectar links internos rotos. Localmente puedes correr `make -f operations/Makefile content-meta` antes de hacer push.

### ¿Cómo valido la paridad bilingüe si edito un solo idioma?
Ejecuta `make -f operations/Makefile parity` para comparar las rutas `knowledge/docs/en/` y `knowledge/docs/es/`. Si la traducción aún no existe, agrega una nota `TODO (parity)` en el archivo y documenta el plan en tu PR para que la canalización no falle.

### ¿Qué pasa si MkDocs ya usa el puerto 8000?
Puedes redefinir el puerto temporalmente con `mkdocs serve -a 127.0.0.1:8010` o exportar `MKDOCS_SERVE_ADDR=127.0.0.1:8010` antes de correr `make -f operations/Makefile docs`.
